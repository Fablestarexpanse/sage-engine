- **M3 S2 design (owner rulings):** scripted behaviour is an ordered rule list stored as data in `sage.mind` (conditions over perceptions and surroundings; command templates); the first matching rule fires. Perceptions between thinks live in an in-memory inbox, lost on restart, until S3 replaces it with memory projected from the log.
- **M3 S2**, ADR 0014. `Component::validate` hook added to core. `sage.mind` and the scripted driver live in `sage-agents`. Gate: 10 agents, 14,400 ticks, 16.5 s, 4,436 commands, `refused=0`. Result: 107 tests passing.
- **M3 S3 design (owner rulings):** hybrid agents consult the LLM only through an explicit `@think` rule action. Memory is to be full generative-agent memory. Split: **S3a** records each occurrence's perceivers in the event (`Occurred` v2, the first real event-schema change, with an upcaster) so memory is an exact projection of the log; adds the LLM driver, `@think`, the injection guard and non-blocking thinking, tested against a stub server. **S3b** adds retrieval (recency, importance, relevance), a rebuildable embedding cache, and reflection and planning stored as agent events.
- **M3 S3a part 1**, ADR 0015. `Occurred` v2 with journal-filled audience, plus `Upcasters::core()` (the first real schema change). A fixture log recorded by old build 2a715f3 is committed as upcaster gate evidence. Memory is projected from the log, and the heard window depends only on log and tick. Found and fixed an overflow in the scheduler's checkpoint check. A mutation showed the process-level kill test can't detect lost memory; the new library restart test can. Result: 114 tests passing.
- **CI failure after c24f050:** the demo-agents kill test diverged on Linux. Root cause: a tick was many separate commits, so a kill mid-tick lost the rest of that tick. Reproduced by a deterministic crash-on-Nth-append test before fixing. Fix: each tick is one log transaction (`EventLog` groups, journal group undo, `Scheduler::step` wraps each tick in a group). See ADR 0015's amendment. Result: 116 tests passing.
- **M3 S3a part 2**, ADR 0016. LLM driver, hybrid `@think`, worker-thread thinking, reply checks and prompt containment, and `sage run --llm-*`. Dependency: `ureq` 3.4. My design additions: the driver rests after an unreachable model but not after a refused reply; answers older than 40 ticks are dropped. Found and fixed: slow failures were being classified as "late". Not verified against a real model; no local server was available. Result: 127 tests passing.
- **M3 S3b design (owner rulings):** memory importance comes from deterministic rules, with optional per-kind weights in the mind (the model may re-rate through reflection later). Relevance uses embeddings from an OpenAI-compatible `/embeddings` endpoint, cached in a rebuildable, never-canonical store, with deterministic word-overlap scoring when no endpoint is set. Reflection triggers when the summed importance of new memories passes a threshold; the model writes 1-3 reflections stored as `sage.mind.reflected` occurrences that only the agent perceives. Plans are deferred. Build order: (1) component upcasters, `sage.mind` v2, importance, lexical retrieval; (2) embeddings and cache; (3) reflection.
- **M3 S3b part 1**, ADR 0017. Component upcasters in core, `sage.mind` v2, deterministic importance, retrieval selection, lexical relevance with stopwords. A failing test led to adding the 3 always-included most-important memories (my call, recorded for owner review): without them an important tell was crowded out by chatter. Result: 136 tests passing.
- **M3 S3b part 2**, ADR 0018. Embeddings client and cache keyed by exact text (my call: no hash collisions); runs on the worker; falls back to word overlap with a 60 s rest; `--embed-url/--embed-model`. Result: 142 tests passing.
- **M3 S3b part 3**, ADR 0019. Reflection on an importance budget, committed through a native `Reflections` system. Default threshold 50 and a 100-tick backoff after failure (my calls). Result: 148 tests passing.
