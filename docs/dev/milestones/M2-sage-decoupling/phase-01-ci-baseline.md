## Goal

Create the repository's first CI: a GitHub Actions workflow that runs the four Python gates and
the WorldForge vitest suite on every push and pull request. Every later SAGE stage relies on CI
to enforce the brief's invariants (`docs/sage/BRIEF.md` §3), and none exists today
(`docs/sage/PHASE0_AUDIT.md` §11.6).

## Current state

- No `.github/` directory exists.
- `pyproject.toml` declares runtime dependencies only. `ruff` and `pytest` are not declared
  anywhere, so a clean environment can't run the gates. Locally installed versions:
  ruff 0.12.7, pytest 9.0.3.
- `requirements.lock` pins runtime dependencies (generated by `uv pip compile pyproject.toml`).
- Python target: `requires-python = ">=3.11"`, ruff `target-version = "py311"`.
- The pytest suite is hermetic (in-memory fakes in `tests/fakes.py`); `tests/conftest.py`
  disables telemetry. It passes with no Redis or Postgres running.
- `worldforge/package.json` has `"test": "vitest run"` and a committed `package-lock.json`.

## Spec

1. **Declare dev tools** — in `pyproject.toml`, add a `dev` entry under
   `[project.optional-dependencies]`: `dev = ["ruff==0.12.7", "pytest==9.0.3"]`. Do not change
   any other key.
2. **Create the workflow** — create `.github/workflows/ci.yml` named `CI`, triggered on `push`
   (all branches) and `pull_request`. Two jobs:
   - `python` on `ubuntu-latest`: checkout; `actions/setup-python` with `python-version: "3.11"`
     and pip cache; `pip install -r requirements.lock`; `pip install -e ".[dev]"`; then four
     separate steps, one per gate, exactly:
     `python -m ruff format --check src tests`,
     `python -m compileall -q src tests`,
     `python -m ruff check src tests`,
     `python -m pytest -q`.
   - `worldforge` on `ubuntu-latest`: checkout; `actions/setup-node` with `node-version: "22"`
     and npm cache keyed on `worldforge/package-lock.json`; `npm ci` then `npm test`, both with
     `working-directory: worldforge`.
   Pin actions to major versions (`actions/checkout@v4`, `actions/setup-python@v5`,
   `actions/setup-node@v4`). Set `permissions: contents: read` at workflow level. Add
   `concurrency` keyed on workflow + ref with `cancel-in-progress: true`.
3. **Document the gates** — in `docs/dev/STANDARDS.md` §4, add one sentence after the command
   block: CI (`.github/workflows/ci.yml`) runs the same gates with `ruff format --check`, so a
   phase whose local gates pass should pass CI.

## End-to-end verification

The real artifact is the workflow and the clean-environment install it depends on.

1. Create a throwaway venv outside the repo tree, install as the workflow does, and run the four
   gates from it. Quote the tail of each command's output:
   ```
   python -m venv <tmp>/ci-venv
   <tmp>/ci-venv/Scripts/python -m pip install -r requirements.lock
   <tmp>/ci-venv/Scripts/python -m pip install -e ".[dev]"
   <tmp>/ci-venv/Scripts/python -m ruff format --check src tests
   <tmp>/ci-venv/Scripts/python -m compileall -q src tests
   <tmp>/ci-venv/Scripts/python -m ruff check src tests
   <tmp>/ci-venv/Scripts/python -m pytest -q
   ```
   (Use `bin/` instead of `Scripts/` on non-Windows.) If `requirements.lock` fails to install on
   Windows, record the error and install with `pip install -e ".[dev]"` alone; CI runs Linux.
2. `cd worldforge && npm ci && npm test` — quote the vitest summary line.
3. Parse the workflow YAML with the command in the acceptance criteria and quote the output.

Do not push to GitHub; the architect pushes and checks the first real CI run at review.
